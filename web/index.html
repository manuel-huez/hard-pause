TWO WAYS TO PAUSE

Choose how access returns.

01 / FLEXIBLE

Pause

Wait before a short break. When the break ends, the block returns. Ending the plan has its own wait. You can also choose an end time when you create it.

02 / NO BREAKS

Hard Pause

Keep the block in place without breaks or an automatic end. To get access back, ask to end the plan and wait for the time you chose.

If plans overlap, access returns only when every plan that blocks it allows access.

NATIVE ON BOTH PLATFORMS

One rule:
access takes time.

Hard Pause uses local system protection designed for each device.

01iOS 26 or later

iPhone and iPad

The app uses Screen Time to block selected apps and websites while a plan is active.

  • Block the apps and websites you choose
  • Make separate plans with their own waits
  • Make it harder to delete apps during a block

You can change Screen Time permission in iPhone settings. We still need to test the protection on a real iPhone.

02macOS 26 or later

Mac

Close the window and your block stays on. Hard Pause keeps running in the menu bar to check websites.

  • Block apps, websites, and specific pages
  • Make separate plans with their own waits
  • Keep blocks on when you close the window

Some ways of browsing can get around website blocks. A Mac administrator can turn off this protection. Closing a blocked app can lose unsaved work.

Hard Pause is still in development. We are testing how reliably the iPhone blocks apps and how Screen Time setup works on Mac. Read the validation record ↗

PRIVATE

Your rules stay on your device.

No account, usage tracking, or uploaded browsing history. Website lists come from public sources, but checks happen on your device.

HONEST

Protection limits stay visible.

If a block cannot run correctly, Hard Pause tells you in the app.

INDEPENDENT

One block cannot release another.

If two plans block the same thing, both must allow it before access returns.
